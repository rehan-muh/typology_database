Re-audited the public `data/phonetic_measurements/` directory in `pacscilab/voxangeles`. Upstream currently exposes six measurement tables with immutable Git blob identities:

- `voxangeles_f0_quartiles.tsv` — blob `afccf9eb747835743cd59607576361bed556b3d2`, 1,108,220 bytes.
- `voxangeles_formants_deciles.tsv` — blob `e0d8e6de5a5a85c3d1b45fc8c2d8bad8716597c6`, 3,815,394 bytes.
- `voxangeles_formants_quartiles.tsv` — blob `216ee5c99310ac5bfa0fd744370cb0f3912b20f7`, 1,940,962 bytes.
- `voxangeles_meanf0_file.tsv` — blob `9492dd2ed35044219aed483613fd3f7a44f292d3`, 167,365 bytes; this recording-level table is already parsed in the warehouse.

A concrete lineage bug was fixed in `scripts/ingest_voxangeles_manual_layer.py`: the prior ingester concatenated decile and quartile representations into one trajectory output. That could allow alternate measurements of the same audited vowel token to be treated as independent observations downstream. The revised ingester now:

1. keeps deciles as the canonical trajectory representation;
2. writes quartiles to `acoustic_trajectories_alternate_quartiles.csv` only;
3. writes explicit `trajectory_lineage.csv` with no-double-count rules;
4. adds stable namespaced recording/token/lineage IDs;
5. preserves source time-variable names and derives normalized time separately;
6. validates required timing columns, token-ID uniqueness, and nonnegative phone/word durations;
7. expands the source-variable profile toward the required dictionary schema without silently dropping unknown variables;
8. pins each public table to its upstream Git blob in the generated table inventory.

A durable audit was added at `data/warehouse/voxangeles_lineage_audit_2026-09-07_1108.csv` so future runs know exactly which representations are canonical versus alternate.

The GitHub connector still does not stream the multi-megabyte TSV bodies through `fetch_file`, so this run does **not** claim the pending duration/F0/formant rows as parsed warehouse observations. Existing warehouse counters remain 689,031 rows / 70 parsed source tables / 855 variable records.

### soundgen manual pitch layer

Added `soundgen_pitchcontour_anikin_persson` to review. Current `soundgen` documentation exposes `pitchContour` (260 manually corrected pitch-contour records), `pitchManual` (manually verified pitch values), and manual syllable counts for a subset of an existing human-vocalization corpus. This could qualify under the database's secondary-reuse exception because the manual annotation layer is genuinely new and isolable. Admission is deferred because the underlying recordings are described as non-linguistic emotional vocalizations, so scope under the non-singing phonetic-production remit must be decided explicitly.
